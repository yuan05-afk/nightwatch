# NIGHTWATCH method

Living document. Every number here is regenerated by `ml/` and written to `ml/reports/*.json`; this file explains the choices behind them.

## Data

**Corrected CIC-IDS2017** (Liu, Engelen et al., IEEE CNS 2022), regenerated with a fixed CICFlowMeter and relabelled with published logic. We use it instead of the original because more than a quarter of the original flows were mislabelled or malformed (Engelen et al., IEEE SPW 2021).

### Attack schedule (one campaign per family)

| Day | Date | Traffic |
| --- | --- | --- |
| Mon | 2017-07-03 | Benign only |
| Tue | 2017-07-04 | FTP-Patator, SSH-Patator |
| Wed | 2017-07-05 | DoS Hulk, DoS GoldenEye, DoS Slowloris, DoS Slowhttptest, Heartbleed |
| Thu | 2017-07-06 | Web Brute Force, Web XSS, Web SQL Injection, Infiltration, Infiltration Portscan |
| Fri | 2017-07-07 | Botnet (Ares), Portscan, DDoS (LOIC HTTP) |

Consequence: a plain "earlier days train, later days test" split makes every test attack a family the model has never seen. That is the zero-day experiment, not known-attack detection, so we run both and label them honestly.

### Label policy

- "Attempted" flows (attack-window flows with no malicious behaviour) are relabelled **Benign**, as the dataset authors recommend. They are never their own class.
- Fine-grained labels are kept for training; the UI groups them into families: Brute Force (FTP, SSH, Web), DoS (Hulk, GoldenEye, Slowloris, Slowhttptest), DDoS, Web Injection (XSS, SQLi), Heartbleed, Infiltration, PortScan, Botnet.

### Features

Dropped to prevent shortcut learning (Arp et al. pitfall P4, spurious correlations): Flow ID, Src IP, Dst IP, Src Port, Timestamp, and any dataset bookkeeping columns. In this testbed the attacker is almost always `172.16.0.1`; a model that sees IPs learns the lab, not the attack. Destination port and protocol are kept (they are legitimate service context) and a no-port ablation is reported.

## Splits (the Accuracy Illusion)

| Split | What it measures | Why |
| --- | --- | --- |
| Random stratified | Nothing realistic | Shown only to expose inflation: neighbouring flows of the same campaign land in both train and test. |
| **Chronological within campaign** (headline for Detect) | Detecting known attack families later in their own campaign | For every class, flows are ordered by time: first 60% train, next 20% calibration, last 20% test. Benign follows the same rule per day. |
| **Leave-one-family-out** (headline for Doubt) | Behaviour on a family never seen in training | Train and calibrate without one family, then score that family's flows. Success = flagged (Known-other or Unknown), failure = passed as Benign. |
| Cross-year (stretch) | Drift to a new network | Train on 2017, test on corrected CSE-CIC-IDS2018. |

## Metrics

Per-class precision and recall, macro-F1, PR-AUC, false-positive rate on benign. Accuracy is reported only inside the Accuracy Illusion panel. A base-rate table converts benign FPR into expected false alerts per day at realistic volumes (Axelsson 2000; Arp et al. P8).
